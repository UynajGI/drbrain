# 单一 tree 算法审查：PageIndex 源码边界

2026-09-14。按用户最新约束审查：只保留 BM25、vector、tree 三路；tree 是一个统一节点/成员 DAG、一个 walker 和一份排名，不维护 PageIndex 树与 RAPTOR 树再拼接。以下是设计审查，未经实验不承诺检索提升或学术新颖性。

PageIndex 源码依据固定为 [`bfbd4b305cd3f0f39a5094779627a2c93634ad79`](https://github.com/VectifyAI/PageIndex/tree/bfbd4b305cd3f0f39a5094779627a2c93634ad79)。本轮不重新审阅 RAPTOR 数值实现；对软 GMM 的意见针对候选融合方案，不冒称来自 PageIndex 原生能力。

1. **单一 DAG 可以成立，条件是结构只作先验，不保留第二套可检索层级。** Heading path、文献顺序、页/行定位作为叶证据属性；结构候选组与语义候选组进入同一个候选池、同一个父接受门、同一张 `children` 表。不要在每个 node 里分别加 `pageindex_children` / `raptor_children`，也不要为相同证据集合分别创建两套“章节父”和“聚类父”。上游构建中的临时 outline 可作为中间计算产物，用完转成统一候选，不能再成为另一路持久化索引。`origin` 可以记录候选由哪个步骤提出，但不能控制两套不同的检索算法。

2. **从 page span 转成 source span，必须保住文献内顺序与可验证边界。** 叶证据至少携带 `document_revision`、规范正文 block ID 和半开区间、原文件 hash、可用的物理页/页内 bbox、heading path、段落顺序、来源格式和 parser revision。PDF 页是 1-based inclusive；MD heading 是 1-based `line_num`，不能互相冒充。TeX 多文件来源还需要成员文件路径。跨文献父只表示成员集合，不能用所有成员的最小起点和最大终点伪造一个连续范围。标题树父节点的开头 residual、前言和共享边界页需要在原文证据层明确归属，避免漏掉或重复聚类。[PDF 与 MD 接口](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/page_index_md.py#L32)、[PageIndex residual 计算](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/tree_optimize.py#L240)。

3. **单节点 schema 仍要区分原文和生成内容，而不是区分两种树。** 建议统一 `nodes(id, revision, kind, title, summary, state, fingerprint, …)`，`kind` 仅表达 source/aggregate；source node 引用 canonical blocks，不复制正文；aggregate 通过 `children(parent_id, child_id, membership_weight, ordinal)` 引用同一节点表。共享子节点允许多个 parents，因此严格来说是 DAG；必须拒绝环和自包含。完整子树 coverage 从成员关系计算/缓存，summary cache key 包含实际成员 revision 与摘要策略；相同 coverage 是否能合并还要核对摘要用途/策略，不能仅凭相近标题。上游顺序编号 `0000` 在优化后重编，不能直接当稳定证据 ID。[ID 重编](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/tree_optimize.py#L207)。

4. **当前 cost gate 只能当显式假设，不能当“覆盖保证”。** `read_cost(all unique members)` 对比 `summary_cost + max(child_path_cost)` 隐含“单目标、只需一个正确分支且路由选对”。对需要多个段落/文献的题，实际成本可能是多个路径与原文集合的并集；摘要压缩造成的遗漏/错路也不在 `max` 中。软重叠 DAG 还须按唯一 source span 去重，并把未被子候选覆盖的 residual 当可读分支。建议把候选门表述为在指定任务假设下的成本估计：单证据、多证据两种测量分开，记录真实 tool/token 成本和路由错误，不把它称为最优性或最坏情况保证。PageIndex 原式只针对连续页树，也仅把 routing cost 固定估成一页。[原成本假设](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/tree_optimize.py#L1)。

5. **“先判断有收益才生成摘要”存在循环依赖。** 父摘要未生成时，无法知道真实 summary tokens、可路由性或遗漏情况。可执行流程应是：估计上限作便宜预筛 → 通过 IndexModel 生成候选摘要 → 计算实际 tokens、确认所有成员引用与非空覆盖 → 成本/预算复核 → 发布或拒绝父节点。候选/失败记录留在主库的 job/state 中，不形成第二套可查询树；不能在失败时把空摘要父标成 ready。上游 expand 也是先生成并验证候选，再计算收益并提交；它不证明未生成内容的质量。[候选验证及接受](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/tree_optimize.py#L625)。

6. **有限的 heading affinity 必须可解释且保留原始 posterior。** 同一标题字符串在不同文献中的重复（如 Introduction）不应产生结构亲近；先验应基于同一 document revision 内的 heading path/距离。缺失或低可信标题时先验为中性值。保存 GMM 原始 posterior 与调整后的分组分数，限制结构调整幅度；若调整后未重新定义/归一化，不应仍称其为已校准概率。结构先验必须能被跨文献语义证据克服，且不能成为跨篇聚类硬屏障。PageIndex 原生依据实际目录、版式或文中存在的标题，没有概率聚类或这种 posterior 调节；该规则完全是新算法，需无先验/有限先验/硬先验消融。[标题真实性校验](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/tree_optimize.py#L625)。

7. **共享一个 IndexModel 合理，共享的应是调度和摘要契约。** 结构判定与 aggregate 摘要都交给同一 index role；embed/rerank 仍分别承担向量与匹配评分，query-time walker 的模型归 chat/retrieval role。父摘要输入可以复用已经完成的子摘要，但必须保留成员 ID、原文 anchors、关键数值/否定等核查路径。PageIndex 的三类摘要不等价：classic 从节点文本分别摘要，MD 父写 `prefix_summary`，Flash bottom-up 以子摘要加开头原文摘要；不能把它们的已有字符串当同一 coverage 的缓存。4B 能否承担具体上下文/并发预算要测量，统一角色名称不是可用性证明。[MD 摘要](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/page_index_md.py#L10)、[bottom-up 摘要](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/utils.py#L843)。

8. **可以直接复用的代码与需要重写的代码要分开列。** 可调用公开 `md_to_tree` / `page_index_main(..., page_list=...)` 得到临时结构候选；可复用公开源码中的 heading 提取、标题/页号验证、JSON 解析和纯文本摘要辅助函数，但后者不都是承诺稳定的顶层 API，需固定版本契约测试。`page_index_flash` 只收 PDF/BytesIO，没有兼容任意 parser blocks 的入口，直接使用会重新解析 PDF；若要复用解析后的 blocks，需要明确做结构适配。`tree_optimize` 的连续页成本、`summarize_tree` 的页/严格树遍历和局部 summary 跳过策略不能直接应用于统一 DAG，必须改写为 span/成员版本。原生 LocalAPI/DocStore/fixed chat 不应成为新算法运行时依赖。[classic 注入点](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/page_index_classic.py#L1233)、[Flash 输入](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/flash/api.py#L140)。

9. **统一 walker 需要把原生“读结构→读原文”变成状态受控操作。** 任意层 ANN 入口可行，但必须访问当前授权 corpus 的所有已发布层，不能受 BM25 结果硬限制。`expand`、`parents` 都只查同一 `children` 表；`same-doc-neighbors` 从 source order/heading 属性派生，不能偷偷重建第二张 PageIndex parent 图。多父/邻接跳转要求 `(node_revision, action)` visited 集、证据覆盖去重、预算和停止条件，防止 parents/children 循环。全程只有一个 tree 候选账本，按同一规则输出 ranked evidence；遍历次数或多父出现次数不能重复投票。PageIndex 原生 agent 的优势是反复真实读取，而不是一个必须照搬的静态选节点函数。[原生工具循环事件](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/local_chat.py#L719)。

10. **不调用 fixed native chat 是可行选择，但必须诚实标为联合算法。** 可借鉴/复用官方工具失败契约和阅读指令，使用自建 retrieval-only Runner，输出经 `read` 工具回执校验的 node/span/hash；不能拿 PageIndex 输出的答案再当召回片段。上游 `extra_body.tools` 禁止替换其固定工具，普通 chat 不支持工具 history round-trip；因此强行套原生 chat 反而阻碍统一 walker。单独使用 `openai_agent_config` 还不会自动携带 `chat_backend`，新 Runner 必须显式绑定 query model endpoint。最终事实证据仍须下钻原文，聚合摘要与最终答案在 schema 中区分。[固定工具限制](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/local_chat.py#L303)、[endpoint 边界](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/client.py#L1840)。

11. **主 SQLite 保存唯一规范正文可成立，但要取消 leaf text 的再次物化。** `blocks` 持有规范正文一次，leaf nodes 引用 blocks/ranges，aggregate nodes 仅保存新增 summary；FTS external-content 只索引 canonical 文本而不维护另一份正文列。FTS 本身的 posting index、ANN 向量及必要缓存仍是真实派生成本，不能称“零重复存储”。`content.md/tree.json/pages.json` 可按需导出，不能成为后台另一个事实源。保留原文件一份并记录 hash；图片/OCR/附件若不能从原文件廉价确定性恢复，应明确纳入 canonical asset 管理，不能为追求文件少而丢失素材。重建、更新和删除通过 DB transaction/版本发布维护 block、node、FTS 与 ANN 的一致性，不以清空原文件解决。[要替代的原生存储](https://github.com/VectifyAI/PageIndex/blob/bfbd4b305cd3f0f39a5094779627a2c93634ad79/pageindex/local_store.py#L115)。

12. **验收必须能识别“仍然是两套树”与算法退化。** 最小门槛包括：DB 中只有一种 aggregate/member 关系；所有已发布 source span 可从同一 walker 到达且无环；相同证据不会因软多父多次计分；查询只产出一份 tree trace/ranking；没有 SDK store/另存全文。再比较纯 PageIndex 候选、纯 RAPTOR 候选、统一候选池、结构 prior 开关、cost gate 开关、多层入口开关，在单事实/跨段/跨文献题上报告 evidence recall、来源精度、遗漏、tool/model tokens、p95 时间、构建量和增量改动范围。低预算或 ANN 漏召回要明确报告，不能借静默切换其他树掩盖。新规则只有实测优于这些基线后，才可主张工程收益；新颖性还需独立文献检索。

结论：该方向可以满足“一个存储、一种节点关系、一条 tree 路”的要求；落地前应先补齐父成本门的任务假设、候选摘要的两阶段接受、span coverage 和 DAG 状态约束。它是从 PageIndex 源码能力与 RAPTOR 聚类思想发展出来的待验证设计，不是 PageIndex 云端 File System 的复刻。
